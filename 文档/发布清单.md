## 2. 上传包体

**Chrome Web Store**

1. 开发者控制台 → **新增项** → 上传 `发布版/instant-translate-v0.2.1.zip`
2. 等待校验通过（包内 `manifest.json` 必须在根目录，本包已满足）
3. 按下面各节填「商品详情」「隐私权做法」「分发范围」

**Edge Add-ons**

1. Partner Center → **Create new extension** → 上传同一个 zip
2. 依次填 **Availability → Properties → Privacy → Store listings**
3. 提交后认证最长 7 个工作日

## 3. 隐私与数据披露（最容易被打回的一步）

- ⚠️ **必须勾选「网站内容（Website content）」**。
  这不是可选项：用户按下翻译快捷键时，扩展会读取当前页正文并发送给他自己所选的翻译服务。
  漏勾或少勾，属于「披露不实」，会直接导致审核不通过甚至下架。
  `商店文案.md` 第 8 节已经写好了要粘贴的原文。
- ⚠️ **必须提供一个可公开访问的隐私政策 URL**。
  政策全文在 `商店文案.md` 第 9 节。最快的托管方式：新建一个公开 GitHub 仓库开启 Pages，
  或直接用一个公开 Gist，把 URL 填进商店后台。
- 逐条填写权限理由：用 `商店文案.md` 第 7 节的表格，一条一条复制。
  重点是解释清楚**为什么内容脚本要匹配所有网址** —— 这是本扩展最容易被追问的权限。

### 建议截这 4 张

1. **主图**：一篇英文文章，每段下方是中文译文，原文保留 —— 一图讲清「双语对照」

## 6. 审核风险点（提前知道）

| 风险 | 说明与对策 |
|---|---|
| **内容脚本匹配所有网址** | 商店对「全站访问」审查较严。对策：权限理由里讲清楚「用户可能在任何网站读外语内容」，并强调**不主动读取页面内容**。若仍被拒，可考虑改为 `activeTab` + 用户点击后动态注入。 |
| **审核员无法测试翻译** | 本扩展没有任何默认可用的在线引擎，审核员按下快捷键可能什么都看不到。对策：**务必填审核备注**，引导他们选「本地演示（无需密钥）」，那是离线可用的。 |
| **内置 AI 在审核环境不可用** | 内置 AI 依赖 Chrome 138+ / Edge 148+ 且设备达标，审核虚拟机通常不满足。对策：同上，用「本地演示」演示功能。 |
| **名称含「·」等符号** | 两个商店都允许，但需与 manifest 完全一致，否则后台报错。 |
| **版本号必须递增** | 每次更新都要改 `src/manifest.json` 的 `version` 再重新打包，不能重复上传相同版本号。 |

## 7. 重新打包（改了代码之后）

```bash
cd <源码仓库根目录>
npm install          # 首次
npm test             # 必须全绿
npm run build        # 产物进 dist/
```

然后把 `dist/` 的内容重新做成发布版：

```bash
# 1) 更新解压目录（把 X.Y.Z 换成新版本号）
rm -rf "发布版/instant-translate-vX.Y.Z"
cp -R dist "发布版/instant-translate-vX.Y.Z"

# 2) 重新打 zip —— 必须在 dist 目录里打包，保证 manifest.json 在压缩包根目录
cd dist
zip -r -X -9 "../发布版/instant-translate-vX.Y.Z.zip" . -x "*.DS_Store" -x "__MACOSX/*"

# 3) 校验结构（应看到 manifest.json 在第一层）
unzip -l "../发布版/instant-translate-vX.Y.Z.zip"
```

> ⚠️ **不要在源码仓库根目录打包**。仓库根目录有一个与扩展无关的
> `manifest.json`（内容是 `Edge LLM Runtime`，MV2），还有 4.4MB 的 `.dylib`
> 和几个 `.dmp` 崩溃转储。把它们打进去会直接导致商店校验失败。
